# 具身智能体框架 S1:物理闭环 MVP —— 项目总结

日期:2026-09-18|状态:S1 完成定义十条全部满足
规格:《Embodied-Agent-Framework-Spec v1.0》+《S1 物理闭环实施规格 v1.0》

## 一、我们实现了什么

一句话:**用户用一句中文下达整理指令,固定机械臂在物理仿真中依靠夹爪真实接触,把 3~5 个物体逐个归位到托盘;遇到抓空故障能自主发现并恢复;结果由独立评测器判分,全过程可回放、可复现。**

具体能力:

- **自然语言到行动计划**:DeepSeek 一次请求输出结构化目标与动作序列(拾取/放置),支持显式指派、属性分类("红色放左边")、"其余放中间"、多物体归入同一区域;歧义指令(如"把那个东西收好")返回澄清请求而不是瞎猜。
- **真实物理操作**:Franka Panda 机械臂 + 平行夹爪,PyBullet 刚体动力学,所有抓取靠接触力与摩擦完成——没有瞬移、没有吸附、没有"直接改状态假装成功"。
- **闭环验证**:每次抓取/放置后由 Runtime 强制验证(抬升高度、跟随稳定性、落点区域、支撑、静止),模型无法跳过;最终结果由独立 Evaluator 按隐藏答案评分,即使 Agent 自己认为成功,放错目标照样判 0 分。
- **故障自主恢复**:注入式抓空故障(首次抓取叠加 60~85mm 隐藏偏移)能被检测,经历"安全撤退→重新观察→换抓取候选→重试"的恢复链;无恢复时同类故障 100% 失败。
- **工程化基础设施**:6 条 CLI 命令、JSONL 事件日志(schema v1 envelope)、每 episode 的配置快照/关键帧/视频/模型调用记账(含 token 与延迟)、5 个评测集、轨迹与模型响应双回放。

## 二、怎么实现的

### 架构:职责分离的小型 Runtime

```
中文指令 → 任务解释器 → DeepSeek/规则规划器 → 计划校验器
    → 有界 Runtime 状态机(逐步执行+强制验证+预算账本+恢复策略)
        → 技能层(pick/place/observe/safe_retreat)
            → PyBullet 物理后端(IK/关节控制/夹爪/接触)
    → 独立 Evaluator(只读物理真值+隐藏评分答案)
```

关键设计决策:

1. **LLM 一次输出完整计划,不做连续工具调用**。机器人控制频率与云端 API 延迟隔离;执行前可检查完整计划;规则规划器与 DeepSeek 共用同一输出契约,使"恢复开关"可以做严格的配对实验。
2. **信息隔离用依赖注入强制**。Agent 侧组件(规划器/技能/恢复)的构造函数里不存在真值通道,反向测试保证这一点;只有独立 Evaluator 能读隐藏评分答案——"模型自述成功"和"任务判分成功"是两个不同的事件。
3. **三层校验**。LLM 输出:JSON mode + Pydantic schema + 语义校验(实体/技能/前置条件);执行层:IK 解的关节限位检查;物理层:抓取证据 = 抬升高度 + 随末端移动 + 夹爪接触,三者联合,只检测到接触不算抓住。
4. **有界性**:7 类预算(技能调用数、单对象重试、重规划、模型请求、无进展连击、单技能仿真时长、墙钟)全部覆盖验证失败分支,不存在无限循环。

### 调试中解决的真实物理问题(这部分是工作量的大头)

- **PyBullet IK 会返回违反关节限位的解**(DLS 求解器的限位参数形同虚设),伺服永远到不了目标——改用影子状态从标准种子求解,物理执行世界不被污染;
- **机械臂瞬移回初始位姿后,重力下坠的臂体扫飞了桌上的物体**——瞬移后立即锁定位置控制;
- **托盘侧壁几何参数写反**,物体根本没落进托盘而是架在墙顶,此前的"成功"部分是假象——重建托盘几何;
- **释放高度不当导致长方体翻倒**——改为自适应落座检测,落座才松爪,不压死也不空投;
- **关节空间插值的臂体扫掠会撞飞工作区内的物体**——两段式接近(先升高再下降)+ 接触式步进抓取;
- **系统代理失效导致所有 API 请求静默超时**——适配器默认直连,代理策略可配置。

这些问题的共同教训:**仿真里"看起来成功"和"物理上成功"之间隔着大量此类细节,这也是为什么需要事件级日志和独立验证**。

## 三、效果怎么样

固定 90 集验收集(3/4/5 物体各 30 集)+ 30 个冻结故障配置的配对实验,全部在线真实调用:

| 指标 | 结果 | 验收门 |
|---|---|---|
| 规则基线完整任务成功率 | **81/90 = 90.0%**,95% CI [0.821, 0.946] | ≥80% ✓ |
| 在线 DeepSeek 端到端成功率 | **80/90 = 88.9%**,95% CI [0.807, 0.939] | ≥80% ✓ |
| 恢复增益(故障配对) | **+63.3 个百分点**,聚类 bootstrap 95% CI [0.467, 0.8] | ≥20pp 且下界>0 ✓ |
| 无恢复对照组 | 0/30 与 0/90 全失败 | 证实故障真实、无隐藏兜底 ✓ |
| 负例(歧义/非法/越界) | 12/12 预算内澄清或终止,非法动作零执行 | ✓ |
| 分层成功率 | 3 物体 96.7% / 4 物体 90% / 5 物体 80% | — |

在线调用记账:90 集 105 次请求、98,206 tokens、平均延迟 1.54 秒、重规划 15 次。

**最有说服力的一组数字**:同一批冻结故障配置下,关闭恢复 0/30 全部失败(故障是真实的、物理的),开启恢复 19/30 成功(19 胜 0 负 11 平,符号检验 p≈2⁻¹⁹)——恢复能力的增益不是统计噪声。

## 四、诚实的边界

- 属性(颜色/形状)来自特权状态,S1 尚未接视觉;感知是下一阶段的第一个候选方向。
- 抓取候选是几何启发式(顶面中心+横向偏移),不是学习型抓取。
- 转移采用开阔场景的"抬升—平移—下降"栅栏策略,不声称通用避障。
- 恢复只覆盖抓空一类故障;其余类型(IK 不可达、目标满等)做到正确分类与有界终止,不声称能恢复。
- 自建评测集(TabletopOrganize-v1),不是公共 benchmark;成功率只在声明的任务域内有效。

## 五、下一步

按规格约定,S1 结束后由错误分布决定方向:当前 5 物体任务成功率(80%)低于 3 物体(96.7%),主要损失来自多物体同盘放置的物理干扰与槽位约束——这指向操作技能与运动规划的扩展,或引入 RGB-D 感知减少对特权状态的依赖。
